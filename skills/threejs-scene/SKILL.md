# Three.js scene conventions

## Canvas setup

Keep exactly one `<Canvas>`, in `src/scene/Experience.tsx`:

```tsx
import { Canvas } from "@react-three/fiber";
import { Suspense } from "react";

export function Experience() {
  return (
    <Canvas
      dpr={[1, 2]}
      camera={{ position: [3, 2, 5], fov: 45, near: 0.1, far: 100 }}
      gl={{ antialias: true, powerPreference: "high-performance" }}
    >
      <Suspense fallback={null}>
        <Lights />
        <Product />
      </Suspense>
    </Canvas>
  );
}
```

- Clamp `dpr` to `[1, 2]`; never use the raw device pixel ratio on high-density phones
- Enable `shadows` only when the design needs real-time shadows
- Use `frameloop="demand"` for scenes that are static until the user interacts, and call `invalidate()` after changes
- React Three Fiber already sets sRGB output and ACES Filmic tone mapping, so do not set them again
- The canvas takes the size of its parent. A parent with no height gives a blank page
- `Experience` is loaded lazily by `App.tsx`, so it must be a named export from `src/scene/Experience.tsx` and must not be imported anywhere else in the entry bundle

## Check the installed API first

The examples here show the pattern. Before using a React Three Fiber or drei helper, confirm it exists in the installed version: read the versions table in `docs/architecture.md`, and check the type definitions in `node_modules/@react-three/` when unsure. Helpers are renamed and props change between major versions.

## Loading progress and readiness

The UI cannot import drei, so the scene reports progress into the store:

```tsx
import { useProgress } from "@react-three/drei";
import { useEffect } from "react";
import { useSceneStore } from "@/state/sceneStore";

export function LoadReporter() {
  const { progress } = useProgress();
  useEffect(() => {
    useSceneStore.getState().setLoadProgress(progress);
  }, [progress]);
  return null;
}
```

- Set `sceneReady` in the store, and `ready` in the test hook, only after assets have loaded and the first frame has rendered
- A scene with no downloadable assets reports no progress; set `sceneReady` after the first frame instead of waiting for `useProgress`

## Test mode

When the URL has `?test=1` in a development or test build (see the state-management skill for `testHookEnabled`):

- Stop auto-rotation and idle animation, and use a fixed seed for anything random
- Honour the camera and selection parameters defined in the contracts, such as `&camera=front`
- Register the scene queries QA needs with `updateTestHook({ scene: { ... } })`, for example an object's screen position or the camera distance
- Set the hook's `ready` to false when a camera move or transition starts, and true when it settles

## Structure

- One component per scene object in `src/scene/objects/`
- Lights in `src/scene/lights/` and camera rigs in `src/scene/cameras/`
- Use materials and shaders from `src/scene/materials/` and `src/scene/shaders/`; do not define them inline
- Group related meshes with `<group>` and position the group, not each mesh

## Loading models

```tsx
import { useGLTF } from "@react-three/drei";
import type { ThreeElements } from "@react-three/fiber";

export function Product(props: ThreeElements["group"]) {
  const { scene } = useGLTF("/models/product.glb");
  return <primitive object={scene} {...props} />;
}

useGLTF.preload("/models/product.glb");
```

- Always load inside `<Suspense>`
- Preload models needed for the first view
- Use the typed components generated by the technical artist when they exist
- Type props with `ThreeElements` from `@react-three/fiber`, not the global `JSX` namespace, which newer React versions no longer provide
- `useGLTF` caches by URL, so two components using the same file share one scene object and only one of them will show. For a second copy use drei `Clone`, or instancing for many copies. Plain `scene.clone()` breaks skinned and animated models
- Paths start at the site root (`/models/product.glb`) and are case sensitive in production even when they are not on your machine. If the app is deployed under a sub-path, build the URL from `import.meta.env.BASE_URL`
- After loading, check the model's size and position against the camera; a model exported in the wrong units is the usual reason nothing appears

## Lighting starter

- Image-based lighting first, from an HDR in `public/env/`. drei's `<Environment preset="..." />` downloads its file from a third-party CDN, so use presets for quick experiments only and never ship them
- Add at most one shadow-casting directional light
- Use `ContactShadows` or baked shadows instead of real-time shadows where possible

## Animation

```tsx
import { useFrame } from "@react-three/fiber";
import { useRef } from "react";
import type { Mesh } from "three";

export function Spinner() {
  const ref = useRef<Mesh>(null);
  useFrame((_, delta) => {
    if (ref.current) ref.current.rotation.y += delta * 0.5;
  });
  return <mesh ref={ref}>{/* ... */}</mesh>;
}
```

- Always multiply motion by `delta` so speed does not depend on frame rate
- Never call `setState` inside `useFrame`; mutate refs instead
- Read store values in `useFrame` with `useStore.getState()`, not with the hook, to avoid re-renders
- Never allocate objects such as `new Vector3()` inside `useFrame`; create them once outside the loop
- Clamp `delta` (for example to 0.1 seconds) so a long frame or a background tab does not make objects jump
- Timed transitions must end on their exact target value, whatever the frame rate
- With `prefers-reduced-motion`, jump to the end state instead of animating

## Events

- Use React Three Fiber pointer events: `onClick`, `onPointerOver`, `onPointerOut`
- Call `event.stopPropagation()` so only the nearest object responds
- Set the cursor on hover with `document.body.style.cursor` and reset it on pointer out, and on unmount
- Small or thin objects are hard to hit, especially by touch. Add an invisible, larger hit mesh so the target is at least 44 px on screen
- A click that follows a drag should not select. Compare the pointer position on down and up, or use the event's `delta`

## Labels with drei Html

- Keep `Html` labels mounted and toggle their visibility. Mounting or unmounting them during a render causes React "synchronously unmount a root" errors
- Labels overlap when objects are close on screen. Decide the rule with the design spec (hide the lower-priority label, or offset it) and check it at the smallest viewport
- Give labels the global class `.scene-label`, which the frontend developer styles; do not import from `src/ui/` and do not style labels inline

## Robustness

- React StrictMode mounts components twice in development. Every effect that adds a listener, starts a timer or creates a three.js object needs a cleanup function
- Handle `webglcontextlost` and `webglcontextrestored` on the canvas: prevent the default on loss, set `sceneError` in the store if the context does not come back
- Let load errors reach the error boundary around the scene instead of catching and hiding them

## Talking to the UI

- Read and write shared state only through the stores in `src/state/`
- Never import from `src/ui/`

## Disposal

- React Three Fiber disposes of objects it creates declaratively when they unmount
- Dispose of anything you create manually (geometries, materials, textures, render targets) in a cleanup function

## Checklist before handoff

- [ ] The scene renders: you loaded it, or the smoke test did, and saw the first view
- [ ] Frame rate against the target is stated with how it was measured, or labelled Not verified
- [ ] No three.js warnings or errors in the console on load, first interaction and reset; any library warning is recorded with its package and version
- [ ] Camera controls work with mouse, touch and keyboard as specified, and zoom limits stop the camera entering or losing the subject
- [ ] `loadProgress`, `sceneReady` and the test hook's `ready` are set as described above
- [ ] Test mode stops animation and honours the contract's URL parameters
- [ ] Nothing is fetched from a third-party domain at runtime
- [ ] No imports from `src/ui/`; no three.js objects in the store
- [ ] Placeholder geometry, if any, is listed in the handoff note
